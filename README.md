# QQ 机器人管理器

这是一个基于 QQ 官方开放平台的 Flutter 跨平台管理工具，用于配置机器人、收发会话消息及运行插件。界面和系统对话框默认使用简体中文。

## 1.3.3 聊天发送和定位

- 手动发送文字、Markdown、图片、表情或插件命令成功后，聊天定位到最新消息；失败时保留草稿和阅读位置。收到消息及自动插件回复不改变阅读锚点，仍可点击底部新消息提示查看。
- 普通输入框和 Markdown 工作区统一为 Enter 发送、Ctrl+Enter 换行，小键盘回车同样适用。中文输入法选词时不会误发，长按回车不会重复发送；手机键盘使用发送按钮。
- 修复更新下载取消后重复清理临时文件时的异常，下载失败仍会阻止安装。

## 1.3.2 弹窗与四端安装包

- 保存、复制、导出及发送失败等操作反馈统一为可关闭弹窗，重复提示合并并排队；聊天位置不变。
- 更新直接使用完整弹窗，显示更新说明、下载进度、校验结果和安装入口。关闭后本次运行不重复提醒，重新启动仍检查新版；设置可手动打开。
- 修复后台新表头读取旧缓存脚本造成的设备列错位；资源使用独立版本文件名。首页移除大段统计介绍及后台入口，登录页不再公开管理员邮箱，权限限制保持不变。
- 新增 macOS Universal DMG、ZIP 和网站安装说明，包名为 `cn.uuze.botmanager`。测试包尚未经过 Developer ID 签名或 Apple 公证。Windows、Android、iOS 构建流程继续保留。
- 统计说明收纳为简洁的隐私入口，保留停止、删除及首次说明，不隐瞒设备名称和来源 IP 的上报。

## 1.2.6 内置浏览器手机版

- 点击链接仍在应用内浏览页打开，关闭浏览页回到原聊天；网页默认请求手机版。Android/iOS/macOS 使用原生移动内容模式；Windows 使用手机 User-Agent，并在宽屏下以 430 像素的手机宽度显示网页。
- 浏览器右上角可随时切换「电脑版 / 手机版」，在当前浏览页重新加载，不新建系统浏览器窗口；原始链接、参数和片段保持不变，不擅自猜测 `m.` 域名。网站是否提供手机版仍由网站自身决定。
- 手机包名统一为 `cn.uuze.botmanager`，安装包使用当前 Logo，并包含 1.2.5 的引用消息、图片预览、阅读位置和 QFace 修复。
- 「设置 → 关于」仅显示指定的软件介绍、学习用途、作者 QQ（2377130783）和反馈提示，不显示第三方服务说明。

## 1.2.5 引用、图片预览与阅读位置

- 修复引用/嵌套消息重新展开时的 `bool` 与 `double` 类型异常：展开状态和子内容的滚动状态使用独立缓存，支持反复收起、展开和重新进入聊天。
- 修复本机发送的图片只能作为网络 URL 渲染的问题。普通发送和配置发送的本地图片均可显示，历史记录兼容本地路径及 `file:` 地址；点击图片可在应用内放大、缩放和拖动。接收消息不能通过图片地址读取本地文件，本地文件已移动/删除或网络图片不可用时会显示中文原因。
- 新消息不再自动把聊天页拉到底部，即使当前正在底部也保持原来的阅读锚点，底部显示「有 N 条新消息」提示。点击提示可主动查看；切换会话或重新打开聊天页时定位最新消息。收到消息、资料更新或重复事件不会反复触发自动滚动。
- 按用户提供的 [QFace 索引](https://koishi.js.org/QFace/assets/qq_emoji/_index.json) 渲染 QQ 系统表情，按表情 ID 匹配；仅有名称的旧占位记录也可按名称补齐。普通文字、链接、@ 信息、引用和嵌套消息保留。索引一天内复用，失败缓存 5 分钟；只在需要显示表情时获取公共索引，不发送 QQ 凭据、用户 OpenID 或聊天正文。不匹配的特殊表情、索引或图片失效时保留文字说明。优先使用索引里的 PNG，不承诺 Lottie/交互动画效果。
- QFace 来自第三方项目，不是 QQ 机器人资料 API；[项目说明](https://github.com/koishijs/QFace)注明表情资源版权归腾讯，仅供学习交流、不可商用，分发或商用前需确认资源授权。本应用按索引引用远程资源，不将表情图片打入安装包。

## 1.2.4 自动昵称与关闭确认

- OIAPI 单聊昵称查询现在默认开启，无需进入设置开启或保存。旧版已保存的关闭默认值在首次升级时自动迁移，已有单聊打开时及新收到单聊消息时自动查询缺失的昵称。
- 移除设置中的「会话资料」卡片、开关和保存按钮，日常使用无需手动配置。第三方服务不可用时仍保留原名称，可在聊天「会话信息」查看查询状态或手动刷新。
- 默认关闭窗口时弹出「退出程序 / 隐藏到托盘」选择，支持取消；未勾选「以后不再显示」时只执行本次选择，下次关闭继续询问。勾选后记住所选行为，重启仍生效。在设置中开启「关闭窗口时隐藏到系统托盘」并保存，也会跳过弹窗直接隐藏。托盘菜单的「退出程序」始终直接退出。

## 自定义窗口、托盘与单聊昵称

- 桌面端隐藏原生标题栏及边框，统一使用蓝白自定义标题栏；最小化、最大化/还原、关闭按钮在聊天、设置和内置浏览器等路由中保持可用。标题栏空白处可拖动、双击最大化/还原，窗口边缘仍可拖动调整大小；最小桌面窗口为 960 × 640。手机端不加载窗口/托盘管理，也不显示桌面按钮。
- 在「设置 → 连接 → 桌面窗口」选择「关闭窗口时隐藏到系统托盘」并保存。**默认不强制驻留**；关闭按钮和 Alt+F4 使用同一确认流程，开启托盘偏好时只隐藏窗口、机器人继续运行，不再弹窗。未开启时按确认选项退出或隐藏；记住退出后如需重新询问，可在该设置中点击「恢复关闭确认」并保存。最小化按钮始终最小化到任务栏，不与关闭行为混淆。
- 单击托盘图标恢复窗口，右键菜单提供「显示窗口」和「退出程序」；退出菜单始终彻底退出，不会再次隐藏。真正退出前刷新本地聊天存储并清理机器人连接；隐藏窗口不执行退出清理。Windows 下检查托盘可用性，初始化失败或图标失效时保持窗口可见并显示警告；取消托盘选项会先恢复隐藏窗口再移除托盘图标。Linux 托盘依赖 `libayatana-appindicator3-dev`，GNOME 还需 AppIndicator 扩展；macOS/Linux 源码兼容，尚未在本机实测。
- Windows 构建带有内置浏览器关闭补丁 `windows/patches/webview_shutdown.cmake`，对应上游 [WinRT 组件退出时崩溃问题 #2733](https://github.com/pichillilorenzo/flutter_inappwebview/issues/2733)。在构建目录复制并修补该插件的原生源文件，主窗口 `WM_DESTROY` 时提前释放 Composition 资源，退出采用正常关闭流程且在 COM 反初始化之前销毁窗口；不改动共享 Pub 缓存。升级 Windows WebView 插件时需重新审核此补丁，程序按单 Flutter 引擎/主窗口设计。

- 默认启用 [OIAPI 单聊昵称查询](https://oiapi.net/index/doc?id=113)。打开或新收到的单聊缺少平台昵称时才查询，已有 QQ 事件昵称优先，不查询群聊或机器人自己的昵称。设置中不再提供单独的会话资料入口；高级配置字段 `enableOiapiNickname` 仍保留读取兼容。
- 固定请求 `https://oiapi.net/api/Openid`，参数只有机器人 `appid` 与原单聊事件 `author.id`（无原事件时使用会话的用户 OpenID）。这是第三方服务，不是 QQ 官方接口，默认开启会提交这两个标识。不提交 ClientSecret、QQ Token、聊天正文或附件，不采集接口返回的年龄、装扮等无关资料。使用独立无鉴权 HTTP 客户端，禁止跟随重定向，限制响应 64 KB、总超时 10 秒。
- 仅接受 `code=1`、匹配的 `data.openid` 和非空 `data.nickname`；错误提示不能充当昵称。成功后更新单聊列表、聊天标题与历史占位姓名并持久保存，不重复派发消息、增加未读或发送 QQ 消息。成功昵称缓存 1 小时，失败缓存 5 分钟，后台查询至少间隔 2.1 秒，最多排队 32 个；手动「刷新会话资料」可重试。更换 AppID 不复用旧查询缓存。已经发送给第三方的数据无法撤回，已取得的昵称保存在本地。

## QQ 用户头像与官方群资料

- 会话列表、聊天标题和消息头像统一显示已获得的群名、昵称和头像。新事件缺少姓名或头像时保留已有资料，不再把群成员头像清空，也不会用群成员头像代替群头像。
- 自动后台调用官方 [获取群基本信息](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_groups_group_openid_info.get.html) 与 [获取群成员信息](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_groups_group_openid_members_member_openid.get.html)。两者目前需要白名单权限，群成员接口仍为内邀接入；返回 `11253` 时显示授权提示并停止该类自动重复查询。可在聊天右上角「会话信息 → 刷新会话资料」中于获权后重试。
- 群资料缓存 6 小时，成员查询缓存 1 小时；后台查询共享限流队列，请求至少间隔 2.1 秒、最多排队 32 个，不占用消息发送序号。空字段不覆盖已有资料，较晚返回的旧请求不覆盖新的群名、最新消息或未读数；更换机器人凭据后丢弃旧请求结果。
- 用户头像优先使用事件或资料接口提供的实际 URL；缺失时使用 `https://q.qlogo.cn/qqapp/{appid}/{openid}/640`，其中 `appid` 来自当前机器人配置，`openid` 使用单聊用户或群消息发送者的 OpenID（群聊中是 `member_openid`），不是群 OpenID、QQ 号或 union_openid。私聊列表、聊天标题、群成员消息及旧聊天记录均支持此备用来源；更换 AppID 后重新生成备用地址，不沿用旧机器人的 CDN 地址。图片请求不携带机器人 Token 或密钥，加载失败回退文字占位。
- 单聊昵称优先读取 [单聊消息事件](https://bot.q.qq.com/wiki/develop/api-v2/autogen/event/c2c_message_create.html) 的发送者资料，缺失时默认使用上面的 OIAPI 备用来源。CDN 只提供用户头像，不能查询昵称，也不用于拼接群头像；群名、成员昵称仍受资料接口权限限制。单聊事件不保证昵称，文档未列出机器人可任意查询单聊用户完整资料的通用接口。QQ 互联的登录用户信息接口不能直接使用机器人 Token 代替用户授权。
- 机器人自己的昵称/头像通过 READY 与官方 [获取机器人详情](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/users_me.get.html) 补齐。头像加载失败时退回文字占位，不影响聊天。已有保存资料与旧配置保持兼容；资料 API、权限和异常情况使用模拟响应测试，未用真实账号申请或探测权限。

## 配置和发送

1. 在「设置」填写开放平台的 AppID 和机器人密钥，点击「测试凭据」验证，再保存并连接。
2. 默认生产接口为 `https://api.bot.qq.com`，已保存的旧版生产地址会自动迁移；自定义代理地址保留。旧版沙箱需要单独启用。
3. 让用户在 QQ 中私聊机器人，或在群中 @机器人，即可收到会话。平台开启“接收所有消息”后，也可接收未 @ 的普通群消息。手动新建会话需填写事件里的 OpenID，普通 QQ 号和群号不能替代。
4. 普通输入框和 Markdown 工作区都用回车发送，Ctrl+回车换行，也可点击发送按钮。点击「自定义 Markdown」打开独立工作区并实时预览。两种编辑器分别保存草稿，发送失败不会清空。普通框中的代码块仍自动识别为原生 Markdown，正文换行和缩进保留。

## 1.2.0 使用改进

- **内置浏览器**：聊天正文、Markdown、卡片和附件中的 HTTP/HTTPS 链接均在应用内打开，支持后退、前进、刷新和复制地址。网页请求外部应用协议时会拦截，不会自动启动系统浏览器或 QQ。附件能否内嵌预览取决于网页响应及系统 WebView，不支持的资源可复制地址。
- **Windows 浏览器要求**：需要 Microsoft Edge WebView2 Runtime；缺少时页面会提示安装，不会偷偷切换外部浏览器。浏览器数据保存在应用支持目录，不写到 exe 旁边。构建 Windows 版还需 NuGet CLI。使用 [WebView2 官方运行时](https://developer.microsoft.com/microsoft-edge/webview2/)及 [InAppWebView 官方说明](https://inappwebview.dev/docs/webview/in-app-webview/)。当前覆盖 Windows、Android、iOS、macOS；Linux 会显示不支持提示并允许复制链接。
- **表情兼容**：按 [QQ 群聊富媒体上传说明](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_groups_group_openid_files.post.html)使用 PNG/JPG。GIF/WebP 等支持解码的图片转为静态 PNG（取首帧）；不承诺动图。URL 转存因下载/格式错误失败时，尝试本地下载后以 Base64 直传，整个过程只发送一次最终消息，不额外占用主动发送次数。下载请求不带机器人密钥或 QQ Token；拒绝 HTML 伪图片、超过 5 MB 和超大分辨率。被禁言/限流/权限错误不盲目重试。
- **日志**：日志页右上角可「复制全部日志」或导出 TXT/LOG，两者按从早到晚排列，导出使用带 BOM 的 UTF-8。复制/导出保存点击时的快照。内存保留最近 10,000 条，界面有数量和上限提示；关闭「启用日志」后不再记录新日志。分享前请检查个人信息。
- **聊天定位**：重新进入聊天、切换会话、手动发送成功时定位最新消息；接收消息和自动回复保留阅读位置并显示底部提示。图片或多行正文加载后不依赖单次估算滚动高度。
- **Markdown 工作区**：宽屏左右编辑与实时预览，窄屏「编辑 / 预览」切换；提供标题、粗体、代码块和链接快捷插入。预览不会触发 QQ 发送。实际语法/图片支持以 QQ 客户端及开放平台权限为准。
- **清理无效入口**：删除设置页无实现的好友、群聊、事件等导航、无作用的关注会话表单和定时任务占位。群聊/单聊收发、消息设置、插件、凭据验证等有效功能保留。统计改用真实会话数量，旧配置字段保留读取兼容。
- **品牌与包名**：应用内 Logo、Windows 图标、Android 启动图标、iOS AppIcon 均由 `assets/branding/logo.png` 生成；可用 `dart run flutter_launcher_icons` 重建。Android applicationId/namespace 与 iOS bundle identifier 均为 `cn.uuze.botmanager`。更换包名后手机端会视为新应用，旧应用数据不会自动迁移；iOS 重签需使用匹配新包名的描述文件。

当前源码版本为 1.3.3+14。旧版已下载的安装包不会因源码变更而更新，需重新构建后安装。Windows 不能本机构建 IPA 或 macOS 应用，需 macOS CI 编译；IPA 安装前仍需有效证书重签。

Windows 原生浏览器自测入口为 `tool/browser_smoke.dart`：仅启动本机临时 HTTP 服务验证 HTML、JavaScript 和应用内导航，不初始化机器人配置或连接 QQ。维护者可用 `flutter build windows --release --target=tool/browser_smoke.dart` 构建并运行该测试；结果写入 `build/browser-smoke-result.json`。测试后务必用 `flutter build windows --release --target=lib/main.dart` 重新构建正式程序再分发。

窗口/托盘原生自测入口为 `tool/window_smoke.dart`：只使用内存中的临时窗口配置，不读取机器人凭据、不连接 QQ。验证窗口最大化/还原、最小化恢复、关闭确认、单次托盘隐藏恢复、记住选择、原生关闭拦截和真正退出，生成 `build/window-smoke-result.json`、标题栏预览 `build/window-smoke-preview.png` 与关闭弹窗预览 `build/close-dialog-smoke-preview.png`。同样必须在测试后重新构建 `lib/main.dart`，不能把自测程序当正式包分发。

输入示例：

````markdown
# 代码示例
```python
# 中文注释
if True:
    print("你好")
```
````

原生 Markdown 使用 `msg_type: 2` 和 `markdown.content`，不会混入普通文本的 `content` 字段。若平台明确返回代码块格式无效，会保留原文尝试普通文本发送，并在日志中说明；其他错误保留输入并展示原因和接口错误码。

Markdown 模板属于旧版兼容功能。只有使用已有模板时才开启「Markdown 模板」，填写模板 ID 和变量；变量值不支持换行，多行代码请使用自定义 Markdown。自定义 Markdown 无需填写模板 ID。

发送时优先使用会话中最新的有效用户消息作为回复来源。群聊回复期限为 5 分钟、每条最多 5 次；单聊为 60 分钟、每条最多 4 次。序号按原消息递增并从历史恢复，避免重启或切换引用后重复。没有有效上下文时按主动消息发送，其权限和频控由 QQ 开放平台决定。

本地图片直传包含文件名，最多 5 MB；更大的图片请压缩或使用公开可访问的图片 URL。Markdown 内嵌图片需要公网 URL，图片和链接是否可用还受开放平台配置影响。

## 在聊天框配置新功能

点击输入框工具栏的「消息设置」图标，配置后点击「应用设置」，再用发送按钮或回车发送，Ctrl+回车换行。应用设置和请求预览都不会发送消息。点击「恢复默认」或输入框里的清除图标可回到原有自动识别模式；设置在切换会话后恢复默认，避免发到其他会话。

- 「消息类型」：明确选择普通文本、Markdown 或富媒体；手动选定普通文本时，即使内容有代码块或以 `/` 开头，也按正文原样发送。Markdown 可开启图片转存校验，转存失败则不发送。
- 「按钮键盘」：填写按钮模板 ID，或逐行添加自定义按钮（最多 5 行、每行 5 个）。按钮可设置跳转/回调/指令、4 种样式、点击后文案、所有人/管理员/指定用户权限、互斥分组、低版本提示和二次确认弹窗。键盘自动搭配 Markdown 发送。
- 「回复与引用」：选择自动回复、主动消息、指定消息 ID 或事件 ID；回复序号可自动递增或手动指定。可填入最近收到的可回复事件。`msg_id` 与 `event_id` 不会同时发送。
- 真正的引用消息：在聊天区点击「回复」，有引用索引的消息可勾选「在 QQ 中显示引用消息」，也可手动填写索引。用户消息从 `message_scene.ext` 的 `msg_idx` 提取；机器人消息从发送响应 `ext_info.ref_idx` 保存并恢复，普通消息 ID 不会被当作引用索引。机器人自己的消息也可引用。
- 富媒体：支持图片、视频、语音和文件，可选择本地文件、输入公网 URL，或直接填写已有 `file_info` 跳过上传。选择富媒体后不需要再输入正文，直接发送即可。本地直传上限为 5 MB，大文件使用公网 URL；尚未接入分片上传。
- 「请求预览」：查看将要发送的 JSON，不包含访问凭证，不上传文件，也不占用回复序号。未上传文件的位置会显示占位提示。

回调按钮订阅 `INTERACTION_CREATE` 事件；仅消息按钮/快捷菜单回调（11/12 类型）会调用确认接口，避免 QQ 一直显示加载。确认只表示事件已收到，业务动作需由插件另行实现；回调数据在日志中查看。

群聊不支持流式参数，自动发送指令、指令引用和唤起选图等单聊专用选项在群聊中禁用。身份组权限仅限频道，本工具当前不发送该字段。按钮模板/自定义按钮能否使用，仍以机器人在 QQ 开放平台的实际权限为准。

## 全量群消息

已接入 `GROUP_MESSAGE_CREATE`，与 @ 群消息共用 `GROUP_AND_C2C_EVENT (1 << 25)` 订阅。需要先在 QQ 开放平台为机器人开启“接收所有消息”；程序不能代替平台授予权限，也无法仅凭没有事件判断权限是否开通。

- 「设置 → 连接 → 处理全量群消息」默认开启，只控制本地接收、保存和展示，关闭不影响 @ 消息。
- 「设置 → 自动回复 → 普通群消息也触发插件和自动回复」默认关闭。关闭时仍允许明确的天气/IP 指令免 @ 调用天气插件，其他普通聊天不回复；开启后额外执行所有已启用插件、关键词和默认回复规则。机器人发送的消息始终不触发自动回复。
- 展示发送者昵称、群主/管理员/成员角色、正文、@ 用户名称和全部附件。图片保留文字说明；语音显示 ASR 参考转写并优先打开 WAV 地址，视频和群文件显示名称、大小及打开入口。音视频不自动播放，打开由用户主动点击后交给系统默认应用，附件下载地址可能过期。
- 支持 ARK 分享卡片（小程序、位置等）的类型、标题、描述、来源、预览图和链接；不在桌面端运行 QQ 小程序。
- 支持并行消息、聊天记录、引用消息（101/102/103）的递归元素展示与折叠。空白正文的引用消息可直接查看元素里的记录，不再被误标为图片。为避免超大消息拖慢界面，递归展示限制为 8 层、200 个元素；原始数据完整保存，可点「详情」查看。
- `message_scene.ext` 的 `msg_idx` 用于引用本条消息，`ref_msg_idx` 保留为被引用消息上下文，两者不会混淆；带 `==` 的索引完整保留。详情查看和复制会隐藏 `auth_token` 等敏感字段。
- 全量消息和 @ 消息按消息 ID 去重，避免重复保存/自动回复；后到的 @ 事件仍可触发一次正常回复。侧栏“本次全量群消息”显示当前运行期间实际处理的唯一全量消息数，不代表平台权限状态。

以上事件结构按用户提供的官方文档补齐；没有使用真实 QQ 账号发送测试消息。

## 高德天气与 IP 查询插件

在「插件 → 天气与 IP 查询 → 配置」中填写高德开放平台的 **Web 服务 Key**，可选填默认城市。原有 `weather_plugin` ID、启用状态和配置会保留。天气改用高德实况数据，不再生成模拟天气；城市名通过高德行政区查询转换为 adcode，编码缓存 24 小时，天气每次重新请求并显示数据发布时间。

- 天气指令：`天气 北京`、`查询天气 上海`、`查天气 深圳`、`/天气 杭州`、`/查询天气 成都`；保留 `/weather 北京`、`/tianqi 北京`。
- 可直接使用六位行政区编码，例如 `天气 110105`。同名区县会提示候选编码，不会自动猜测所在地区。请指定城市或区县，不要只填整个省份。
- 单独发送 `查询天气`、`天气` 或 `/天气` 时，使用已配置的默认城市；没有默认城市则提示用法。
- IP 指令也归这个插件：`查ip地址 114.114.114.114`、`查询IP 114.114.114.114`、`/ip 114.114.114.114`，显示省市和行政区编码。高德基础 IP 定位仅支持国内 IPv4，不支持国外 IP 和 IPv6。
- 单独发送 `/ip`、`查ip地址` 会提示提供地址，不会查询运行本程序的出口 IP 并冒充 QQ 用户 IP。QQ 消息事件不提供发送者 IP；IP 地理定位结果也不代表用户实时位置。
- 缺少 Key、Key 类型错误、权限/白名单问题、超额、超时及无结果都有中文提示。Key 不会出现在插件回复或网络错误中；界面默认隐藏，但本机配置及配置导出仍包含 Key，请妥善保管。

Key 需具备天气查询、行政区域查询与 IP 定位所需权限，实际可用性和额度以高德控制台为准。当前支持普通 Web 服务 Key，不支持数字签名鉴权；程序不会修改高德账号设置。群聊免 @ 需要 QQ 开放平台已经开启“接收所有消息”，且本地“处理全量群消息”开启。无需开启广泛的“普通群消息也触发插件和自动回复”开关：保持它关闭时，只处理天气/IP 明确指令，既不会交给其他插件，也不会兜底发送默认回复。平台不推送全量事件时，客户端无法自行读取未 @ 消息。

接口依据：[天气查询](https://lbs.amap.com/api/webservice/guide/api/weatherinfo)、[行政区域查询](https://lbs.amap.com/api/webservice/guide/api/district)、[IP 定位](https://lbs.amap.com/api/webservice/guide/api/ipconfig)、[错误码](https://lbs.amap.com/api/webservice/guide/tools/info)。自动化测试使用模拟响应，不会调用真实 Key 消耗配额。

## 开发

```bash
flutter pub get
flutter analyze
flutter test
flutter run -d windows
flutter build windows --release
```

界面采用浅色蓝白工作台：独立的总览、聊天、插件和日志页面，手机端使用底部导航。插件中心支持搜索、导入、权限确认、配置、启停、清单复制和第三方插件卸载。

插件真实实现已迁入独立本地 Dart 包 `plugins/`（源码在 `plugins/lib/`），内置清单以 `plugins/*/plugin.json` 为准。开发者可直接编写 JSON/YAML 规则插件或 HTTP 服务插件，通过界面导入，无需重新编译；Dart 源码插件使用公开 SDK 并随应用编译。导入和替换默认停用，不会自动请求外网或发送消息。

开发文档：[插件开发指南](docs/plugin-development.md)。可运行示例：[JSON 规则](plugins/examples/hello_json/plugin.json)、[YAML 规则](plugins/examples/hello_yaml/plugin.yaml)、[HTTP 插件](plugins/examples/http_echo/plugin.json)及[Python 示例服务](plugins/examples/http_echo/server.py)。编辑器校验见 [JSON Schema](plugins/schema/plugin.schema.json)。应用内也可点击「插件 → 开发者文档与示例」阅读和复制。

定时任务尚未实现，其占位入口已移除。配置导入/导出包含凭据和插件设置；重置机器人配置保留聊天记录，清除全部数据需在界面确认。
