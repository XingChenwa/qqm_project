# 本地 AI 翻唱 · RVC

独立本机服务：Demucs 分离人声 → RVC 转换音色 → FFmpeg 混合伴奏。配套 JSON Skill 通过固定的本地 HTTP 接口调用，无需让沙箱插件直接执行系统命令，也不改动 YY TTS。

这台电脑安装在 `E:\QQBotManager\rvc-cover`，使用独立 Python 3.10 环境、CPU PyTorch、Demucs 4.0.1、RVC Python 0.1.5。无 NVIDIA 显卡，处理整首歌曲可能需要较长时间，同一时间只运行一个任务。缓存、基础模型、歌曲和输出都放在 E 盘。

## 使用

1. 打开 <http://127.0.0.1:23339/>。服务未启动时，双击安装目录的 **启动翻唱服务.cmd**。
2. 导入 RVC **推理音色 `.pth`** 和歌曲音频，也可直接把文件放到安装目录的 `models` / `songs`。QQ 音乐支持直接输入歌名搜索，同名或多个版本会列出歌手和完整歌名，选好后导入；已有歌曲详情链接或 MID 也可直接导入。`.pth` 需要包含 RVC 的 `weight`、`config`，训练中间检查点或 YY TTS 的音色名称不能直接当作该模型。
3. 网页可选择歌曲、音色、升降调与试听起点，提交任务，查看真实进度；生成后试听、下载整首 MP3。导入不会覆盖同名文件；本服务不自动清理用户歌曲或模型。
4. 安装支持宿主接口7的管理器，首次打开 QQ Agent 后会出现 **本地 AI 翻唱 · RVC**，初始关闭。手动启用，并在当前 AI 预设中选中；模型需支持工具调用。也可在 Skills 手动导入安装目录的 `skill.json`。未自行修改过的旧配套 Skill 会在升级客户端后自动更新，保留原启用状态、设置和预设绑定；自定义过提示词或工具的版本会保留原样，并在运行日志提示手动合并。
5. 聊天示例：“检查翻唱环境”“有哪些音色和歌曲”“用某音色翻唱某首歌”。开始只提交后台任务；稍后说“查看翻唱进度”，完成后说“把翻唱发出来”。聊天发送5–60秒试听，整首留在本地网页下载。

十个工具：`rvc_cover_search_qq`、`rvc_cover_select_qq`、`rvc_cover_import_qq`、`rvc_cover_health`、`rvc_cover_models`、`rvc_cover_songs`、`rvc_cover_start`、`rvc_cover_status`、`rvc_cover_cancel`、`rvc_cover_send`。任务按机器人账号和当前会话隔离；发送必须收到实际消息回执，不把原曲当作翻唱、也不把排队当作已完成。

### 聊天中选歌

用户说“用芙宁娜音色唱《唯一》”，Skill 会先检查本地资源，缺歌时直接搜索 QQ 音乐，无需让用户自己找链接。遇到多个版本，机器人在原会话向原提问者列出“序号 · 歌名 · 歌手”，本轮结束等待选择。例如原提问者回复“选2”或列表中的歌手名后，再确认导入。群聊仍按当前连接的唤醒规则使用，必要时 @ 机器人。

候选列表保留20分钟，按机器人、会话和提问者隔离。不同用户不能替他选择；同一歌手有多个版本时须用序号。候选序号从1开始，以实际搜索结果为准，不能固定把某个序号当作某位歌手。超时、服务重启后重新搜索。只有一个候选时可以直接确认；没找到时请补充歌手或版本。

`select_qq` 的聊天工具只有可选参数 `search_id`，可直接调用来选择当前提问者本会话最近的列表，不依赖模型跨轮记住工具返回的内部ID。选择内容来自宿主固定传入的 `caller.id`、`caller.messageId`、`caller.text`，不读取模型编造的确认参数，也不把引用记录当作本人确认。网页有独立的候选导入按钮。未确认多版本前不会下载；重复确认不会重复创建导入任务。

搜歌使用 QQ 音乐公开的歌曲联想接口，列出当前返回的候选，列表不是完整曲库。查询词只包含歌名和所需的歌手 / 版本，不发送完整聊天内容。确认后使用用户指定的 [接口文档](https://api.avbvcv.xyz/doc) 中 `qm_song_download` 导入，只接受相同 HTTPS 服务源的 `/qmmer/file/` 限时下载链接，最大64 MB，下载后通过 FFmpeg 验证并转为本地 MP3。导入失败不会建立可用歌曲，也不会把下载完成当作翻唱完成。服务器可能受版权范围、接口变化、限时链接或网络影响；无需把 QQ / AI / Git 密钥交给本服务。

音色按用户选择稍后导入：没有音色时环境检查会列出缺项，不能生成真实的指定音色翻唱。人声分离和混音可以单独自检，不等于已经通过音色转换测试。

## 服务边界

只监听 `127.0.0.1:23339`，不是公网服务。检查 Host / Origin，状态变更需要 `X-QQM-Cover: 1`；不开放跨站 CORS。Skill 只能提交固定动作和目录中的素材ID，不接受任意命令、外部文件路径或任意下载地址。不读取模型服务、QQ 机器人、GitHub / GitCode 的凭据。

本机服务要与管理器同时可用。手机不能通过自己的 `127.0.0.1` 连接这台电脑；当前配套 Skill 用于本机 Windows。服务不会自动注册系统服务、定时任务或开机启动。需要停止时运行 `Stop-Service.ps1`；它只终止本安装目录记录、且仍匹配的进程树。

基础模型由 RVC Python 上游指定的 [RVC_Base](https://huggingface.co/Daswer123/RVC_Base) 获取并核验 SHA-256：HuBERT 与 RMVPE 是特征 / 音高模型，**不包含用户要选择的歌声音色**。CPU 路径不下载未使用的 ONNX GPU 模型。

代码依赖来源：[RVC Python（MIT）](https://github.com/daswer123/rvc-python)、[Demucs（MIT）](https://github.com/facebookresearch/demucs)、[fairseq（MIT）](https://github.com/facebookresearch/fairseq)、[FFmpeg](https://ffmpeg.org/)。本桥接代码随项目使用 GPL-2.0，模型和输入音乐的条款以各资源来源为准；模型权重不放进客户端安装包或源码仓库。

## 环境维护

`constraints.txt` 记录关键版本；安装结果另存 `requirements-installed.txt`。fairseq 的 PyPI 0.12.2 源码包缺少 C++ 源文件，本机改用官方 `v0.12.2` 提交 `4a388e64cd646ed7d7ad8de8fae55df2b8eea91d` 编译，无需修改上游源码或跳过实际推理依赖。不要直接用当前系统 Python 替换专用环境。

服务源码在安装目录 `service`，配置为 `config.json`，日志在 `logs`，每个后台任务在 `jobs/<id>` 下。`Deploy-Service.ps1` 只部署已安装环境的服务代码和 Skill，不是模型训练器，也不包含歌曲与音色。
