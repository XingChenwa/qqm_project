版本发布

上传先保存为草稿；确认发布后才进入客户端更新与首页下载。强制更新打开后，旧客户端不能点稍后跳过。

平台 / 架构版本 / 构建大小状态强制更新操作

Windows 支持 ZIP 原位更新及 Inno Setup EXE；Android APK 必须与已安装版本签名一致。iOS IPA 安装前需重签。macOS 使用 DMG，打开后拖入“应用程序”。发布后客户端每5分钟检测一次，而不是持续占用 PHP 长连接。

部署与安全检查

EdgeOne 使用默认的 EO-Connecting-IP 传递客户端 IP。免费版可在服务器配置 proxy_trust_mode = edgeone_token 并开启 require_origin_token，校验回源密钥后读取该头，不要求付费版回源网段。默认 cidr_and_token 仍要求密钥和可信网段同时匹配。

免费版模式必须使用 HTTPS 回源，并在 EdgeOne 覆盖回源密钥。它不替代源站防火墙；密钥泄露后需更换回源密钥，不要更换软件更新私钥。

客户端更新配置

在服务器运行 php bin/manage.php public-key，将公开公钥通过 --dart-define=UPDATE_PUBLIC_KEY=... 内置进首次发布的客户端。不要把签名私钥放到客户端、Git 或聊天。

  1. 宝塔运行目录必须设为应用目录内的 public，不要把 config.php 或 data 暴露到公网。
  2. 在 config.php 填写宝塔 MySQL 和杂鱼账号凭据，运行 php bin/manage.php install 自动生成密钥及数据表；重复安装保留有效密钥。
  3. /api/* 与 /admin* 不缓存、不做 HTML/JavaScript 改写。
  4. 更新包使用带 SHA-256 的不可变路径，可长缓存。撤下后仍需清理 EdgeOne 已缓存的文件。
  5. EdgeOne 用“设置/覆盖”加入 X-QQM-Origin-Token，不要追加；实际值只在本机 CLI 查看。
  6. 免费版使用密钥模式；有实际回源网段时可保留严格模式并配置防火墙。两种模式都使用 HTTPS 回源，不信任任意 X-Forwarded-For。

完整步骤见部署包内 README.md 与 docs/update-and-edgeone.md（源码位于 management 目录）。

上传新版本

构建号不能重复。先保存草稿，再检查并发布。上传时即可勾选强制更新，已有版本可在列表的“强制更新”列开关。大于 PHP 上传限制的文件可用 CLI 导入。
